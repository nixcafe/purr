    mkFlake Usage

    mkFlake builds a flake from a project directory without flake-parts. The call returns the complete outputs attrset.

    Basic usage

    {
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    purr.url = "github:nixcafe/purr";
  };
 
  outputs = inputs:
    inputs.purr.lib.mkFlake {
      inherit inputs;
      src = ./.;
      namespace = "myproject";
      outputsBuilder = { pkgs, ... }: {
        formatter = pkgs.nixfmt;
      };
    };
}

    Hydra CI

    hydraJobs mirrors buildable outputs and adds jobs from a hydraJobs/ directory:

    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  hydraJobs = {
    enable = true;
    systems = ["x86_64-linux"];
    include = [ "checks" "packages" "nixosConfigurations" ];
  };
}

    See the hydraJobs page for the full reference.

    Customizing systems

    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  systems = [ "x86_64-linux" "aarch64-linux" ];
}

    Custom module directories

    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  moduleTypes = {
    nixos = ["nixos" "shared" "container"];
  };
}

    Systems and homes

    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  systemsDir = "systems";   # or "hosts", or null to auto-detect
  homesDir = "homes";
}

    Per-host inputs (multi-nixpkgs)

    inputsFor selects which inputs purr builds from. A host then points at one of those inputs with meta.roles.<role>. Modules always keep the original inputs argument. The replacement only affects how purr builds pkgs, system configs, home configs, and the merged lib. See Host Meta: roles for the role reference.

    # flake.nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-25.05";
    nixpkgs-unstable.url = "github:NixOS/nixpkgs/nixos-unstable";
    purr.url = "github:nixcafe/purr";
  };
 
  outputs = inputs:
    inputs.purr.lib.mkFlake {
      inherit inputs;
      src = ./.;
      inputsFor = { inputs, ... }: {
        inherit (inputs) nixpkgs;
        inherit (inputs) nixpkgs-unstable;
      };
      hosts.server.meta.roles.nixpkgs = "nixpkgs-unstable";
    };
}

    The same role can be set in meta.nix:

    # systems/x86_64-linux/server/meta.nix
{ roles.nixpkgs = "nixpkgs-unstable"; }

    Supported role keys are nixpkgs, home-manager, and nix-darwin. Homes inherit their linked system's nixpkgs; unmatched homes use the effective-input default.

    Formatter

    A per-system formatter is discovered from formatters/ or formatter/. The default.nix receives { pkgs, lib, system, namespace, inputs, ... } and must return a derivation:

    # formatters/default.nix
{ pkgs, ... }: pkgs.nixfmt-rfc-style

    This produces formatter.<system>, which nix fmt uses. outputsBuilder can override it:

    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  outputsBuilder = { pkgs, ... }: {
    formatter = pkgs.alejandra;
  };
}

    Packages

    Modules under packages/ are exposed as packages.<system>.<name>. When packagesToPkgs = true (the default), they are also registered in pkgs, so any per-system module or host config can reference them as pkgs.<name>:

    # packages/hello/default.nix
{ lib, ... }: { /* ... */ }
    # checks/lint/default.nix
{ pkgs, ... }: pkgs.hello   # the discovered package

    Each discovered package is wrapped like a callPackage package, so .override and .overrideAttrs work, and packages can depend on each other:

    # packages/wrapper/default.nix
# `hello` resolves from `pkgs`
{ hello, ... }: hello.override { /* ... */ }

    Registration is a nixpkgs overlay built on the package-set fixpoint. One-way dependencies resolve lazily. Mutually recursive packages recurse, as in any nixpkgs overlay.

    Set packagesToPkgs = false to keep packages out of pkgs. They remain available as packages.<system>.<name>:

    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  packagesToPkgs = false;
}

    Legacy packages

    legacyPackages.<system>.* is discovered from legacyPackages/. These packages are not added to pkgs:

    # legacyPackages/hello/default.nix
{ pkgs, ... }: pkgs.hello
    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  legacyPackagesByName = true;   # also scan legacyPackages/by-name/<shard>/<name>/package.nix
}

    Build one with nix build .#legacyPackages.<system>.hello.

    Checks and shells

    checks/<name>/default.nix becomes checks.<system>.<name>, and shells/<name>/default.nix becomes devShells.<system>.<name>:

    # checks/lint/default.nix
{ pkgs, ... }: pkgs.runCommand "lint" { } "true"
 
# shells/dev/default.nix
{ pkgs, ... }: pkgs.mkShell { packages = [ pkgs.git ]; }

    Apps

    apps/<name>/default.nix becomes apps.<system>.<name> and must return a flake app:

    # apps/hello/default.nix
{ pkgs, ... }: {
  type = "app";
  program = "${pkgs.hello}/bin/hello";
}

    Overlays and templates

    overlays/<name>/default.nix becomes overlays.<name>, and templates/<name>/default.nix becomes templates.<name>:

    # overlays/custom/default.nix
_final: prev: {
  hello = prev.hello.overrideAttrs (_: { doCheck = false; });
}
 
# templates/rust/default.nix
{
  path = ./.;
  description = "A Rust project";
}

    Extra args

    Pass custom values to every auto-discovered module:

    inputs.purr.lib.mkFlake {
  inherit inputs;
  src = ./.;
  extraArgs = {
    deploymentTarget = "production";
  };
}

    Modules receive extraArgs values as function parameters:

    # packages/myapp/default.nix
{ deploymentTarget, pkgs, ... }:
pkgs.writeText "myapp" "target: ${deploymentTarget}"

    The keys are passed to packages, shells, checks, apps, templates, system specialArgs, home extraSpecialArgs, and outputsBuilder. purr's own keys (inputs, pkgs, namespace, lib, and similar) override extraArgs on conflict.
